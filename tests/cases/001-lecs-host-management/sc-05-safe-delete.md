## TC-050: 验证运行态主机删除拦截

**优先级**: P1
**追溯**: spec.md → TC-050

### 前置条件

1. 用户已成功登录 Lee 云平台控制台并导航至 `/console/lecs-hosts/list`
2. 系统中存在状态为"正常" (normal) 的主机
3. 系统中存在状态为"创建中" (creating) 的主机
4. 系统中存在状态为"关机中" (stopping) 的主机

### 操作步骤

#### 步骤 1: 验证"正常"状态主机删除按钮置灰
1. 在列表中找到状态为"正常" (绿色标签) 的主机行
2. 查看该行操作列中的"删除"按钮
3. **预期**: "删除"按钮呈置灰状态（不可点击）

#### 步骤 2: 验证"正常"状态主机删除拦截（防御性检查）
1. 若"删除"按钮未正确置灰，尝试点击它
2. **预期**: 弹出提示"请先将主机关机，再执行删除操作"，删除请求被阻止，未弹出确认对话框

#### 步骤 3: 验证"创建中"状态主机删除按钮置灰或拦截
1. 在列表中找到状态为"创建中" (蓝色标签) 的主机行
2. 查看该行操作列中的"删除"按钮
3. **预期**: "删除"按钮置灰，或点击时被拦截并提示

#### 步骤 4: 验证"关机中"状态主机删除按钮置灰或拦截
1. 在列表中找到状态为"关机中"的主机行
2. 查看该行操作列中的"删除"按钮
3. **预期**: "删除"按钮置灰，或点击时被拦截并提示

### 预期结果

- "正常"、"创建中"、"关机中"状态的主机均无法执行删除操作
- 前端按钮置灰提供第一层防护，即使按钮可点击也会被提示拦截
- 无任何删除请求被提交至后端

### 通过标准

- 所有运行态/过渡态主机的删除按钮均不可用或被有效拦截
- 用户看到明确的提示信息，理解为何无法删除

## TC-051: 验证已关机主机的删除流程

**优先级**: P1
**追溯**: spec.md → TC-051

### 前置条件

1. 用户已成功登录 Lee 云平台控制台并导航至 `/console/lecs-hosts/list`
2. 系统中存在状态为"已关机" (stopped, 灰色标签) 的主机
3. 记录当前用户的配额计数（活跃主机数）

### 操作步骤

#### 步骤 1: 点击已关机主机的删除按钮，验证确认对话框
1. 在列表中找到状态为"已关机"的主机行
2. 点击该行操作列中的"删除"按钮（该按钮应可点击）
3. **预期**: 弹出二次确认对话框，提示确认删除操作

#### 步骤 2: 验证取消删除操作
1. 在确认对话框中点击"取消"按钮
2. **预期**: 对话框关闭，主机仍保留在列表中，状态保持"已关机"，无任何删除行为发生

#### 步骤 3: 重新点击删除并确认
1. 再次点击同一主机的"删除"按钮
2. 在确认对话框中点击"确定"
3. **预期**: 主机状态立即变为"删除中" (黄色标签)；该行所有操作按钮（关机、启动、删除）全部置灰

#### 步骤 4: 验证异步软删除完成
1. 等待 3-5 秒
2. **预期**: 该行主机从列表中完全消失

#### 步骤 5: 验证 quota 配额计数减少
1. 检查页面显示的配额计数（如"当前已使用 X/100 台"）
2. **预期**: 配额计数较删除前减少 1

### 预期结果

- 二次确认机制正常工作，取消操作安全无副作用
- 确认后状态立即流转为"删除中"，操作按钮全部禁用
- 约 3-5 秒后主机从列表中消失
- 配额计数正确递减 1

### 通过标准

- 删除流程符合"点击→确认→流转到删除中→从列表消失→配额减少"的完整链路
- 取消操作不产生任何副作用

## TC-API-050: 验证 DELETE /api/v1/lecs-hosts/{id} 删除接口

**优先级**: P1
**追溯**: spec.md → TC-API-050

### 前置条件

1. 调用方持有有效的认证凭证（JWT Cookie 或 Service Token）
2. 系统中存在处于不同状态的主机记录（已关机、创建失败、正常）
3. API 端点 `/api/v1/lecs-hosts` 可访问

### 操作步骤

#### 步骤 1: 验证"已关机"状态主机删除请求
1. 发送 `DELETE /api/v1/lecs-hosts/{id}` 请求，其中 `{id}` 为状态为"已关机"的主机 ID
2. **预期**: 返回 200 接受状态，响应表明删除已接受
3. **预期**: 主机进入"删除中"异步软删除流程

#### 步骤 2: 验证"创建失败"状态主机删除请求
1. 发送 `DELETE /api/v1/lecs-hosts/{id}` 请求，其中 `{id}` 为状态为"创建失败"的主机 ID
2. **预期**: 返回 200 接受状态，响应表明删除已接受
3. **预期**: 主机进入"删除中"异步软删除流程

#### 步骤 3: 验证"正常"状态主机删除被拒绝（403）
1. 发送 `DELETE /api/v1/lecs-hosts/{id}` 请求，其中 `{id}` 为状态为"正常"的主机 ID
2. **预期**: 返回 403 拒绝状态
3. **预期**: 响应体中包含错误提示信息："请先将主机关机，再执行删除操作"

#### 步骤 4: 验证"创建中"状态主机删除被拒绝（403）
1. 发送 `DELETE /api/v1/lecs-hosts/{id}` 请求，其中 `{id}` 为状态为"创建中"的主机 ID
2. **预期**: 返回 403 拒绝状态
3. **预期**: 响应体中包含错误提示信息："请先将主机关机，再执行删除操作"

#### 步骤 5: 验证无认证请求被拒绝（401）
1. 不带任何认证凭证，发送 `DELETE /api/v1/lecs-hosts/{id}` 请求
2. **预期**: 返回 401 未授权错误

### 预期结果

- 仅"已关机"和"创建失败"状态的主机允许删除
- 其他状态下的删除请求均返回 403，并附带明确的中文错误提示
- 无认证请求返回 401
- 合法删除请求为异步处理，返回接受状态后即完成响应

### 通过标准

- 状态校验逻辑正确：仅 stopped/failed 状态可删除
- 错误码返回准确：403 用于状态不允许，401 用于未认证
- 错误消息为"请先将主机关机，再执行删除操作"

## EC-005: 软删除记录在数据库中保留

**优先级**: P1
**追溯**: spec.md → EC-005

### 前置条件

1. 用户已成功登录 Lee 云平台控制台并导航至 `/console/lecs-hosts/list`
2. 系统中存在一台可删除的主机（状态为"已关机"或"创建失败"）
3. 具有数据库直接查询权限
4. 记录待删除主机的 ID

### 操作步骤

#### 步骤 1: 执行删除并确认从列表消失
1. 对该主机执行删除操作（前端 UI 确认或 API 调用）
2. 等待 3-5 秒
3. 刷新列表页
4. **预期**: 该主机记录不再出现在列表中

#### 步骤 2: 直接查询数据库验证软删除记录
1. 通过数据库客户端连接，查询该主机的记录：
   ```sql
   SELECT * FROM lecs_hosts WHERE id = '{主机ID}';
   ```
2. **预期**: 该主机记录仍然存在于数据库中（未被物理删除）
3. 检查 `deleted_at` 字段：
   **预期**: `deleted_at` 字段已填充，值为非 NULL 的时间戳（表示软删除时间）

#### 步骤 3: 验证软删除记录不计入活跃配额
1. 执行配额统计查询：
   ```sql
   SELECT COUNT(*) FROM lecs_hosts WHERE user_id = ? AND deleted_at IS NULL;
   ```
2. **预期**: 该软删除主机不计入查询结果（因为 `deleted_at IS NOT NULL`）
3. 对比删除前后的活跃配额计数：
   **预期**: 配额计数减少 1，与前端显示的配额计数一致

#### 步骤 4: 验证正常查询自动过滤软删除记录
1. 执行应用层正常列表查询（即前端列表页加载时发起的查询）：
   ```sql
   SELECT * FROM lecs_hosts WHERE user_id = ? AND deleted_at IS NULL;
   ```
2. **预期**: 查询结果中不包含该已软删除的主机记录
3. **预期**: 只有 `deleted_at IS NULL` 的记录才会出现在列表中

### 预期结果

- 软删除机制正确工作：数据行在数据库中保留，但 `deleted_at` 字段标记删除时间
- `deleted_at IS NOT NULL` 表示该记录已软删除，对用户不可见
- `deleted_at IS NULL` 表示活跃记录，计入配额计数
- 所有业务查询（列表展示、配额统计）均使用 `WHERE deleted_at IS NULL` 过滤条件
- 软删除记录可通过 `deleted_at` 字段追溯删除时间，满足审计需求

### 通过标准

- 数据库中存在被"删除"主机的完整记录行
- `deleted_at` 字段有值（非 NULL），值为有效的时间戳
- 配额统计 SQL (`WHERE deleted_at IS NULL`) 不将该记录计入活跃数量
- 前端列表不展示软删除记录
