# SC-02: LECS主机列表页与操作矩阵

**优先级**: P1
**质量维度**: 功能适用性、易用性

## 前置条件

1. 系统已完成初始化
2. 管理员账号 `admin` / `admin@123` 已创建
3. 用户已成功登录系统
4. 用户已导航至 `/console/lecs-hosts/list` 页面
5. 系统中存在处于不同状态的主机记录（正常、已关机、创建中、创建失败、删除中）

## 操作步骤

### 步骤 1: 验证列表页基本展示（TC-010）

1. 访问 `/console/lecs-hosts/list` 页面
2. 检查页面是否显示分页数据表格
   - **预期**: 页面渲染分页数据表格组件
3. 检查表格列内容
   - **预期**: 表格包含以下列：主机名/ID、计费模式、运行状态、私有IP、操作列
4. 检查页面标题栏区域
   - **预期**: 标题栏右侧仅显示"创建LECS主机"按钮，无其他全局工具栏元素
5. 检查每行的操作列
   - **预期**: 每行操作列均显示三个按钮：关机、启动、删除

### 步骤 2: 验证状态标签彩色渲染（TC-011）

1. 查看列表中各主机的运行状态列
2. 检查不同状态对应的标签颜色：
   - 找到状态为"正常" (normal) 的主机行
     - **预期**: 状态标签显示为绿色
   - 找到状态为"已关机" (stopped) 的主机行
     - **预期**: 状态标签显示为灰色
   - 找到状态为"创建中" (creating) 的主机行
     - **预期**: 状态标签显示为蓝色
   - 找到状态为"创建失败" (failed) 的主机行
     - **预期**: 状态标签显示为红色
   - 找到状态为"删除中" (deleting) 的主机行
     - **预期**: 状态标签显示为黄色

### 步骤 3: 验证"正常"状态主机的操作矩阵（TC-012）

1. 在列表中找到运行状态为"正常" (normal) 的主机行
2. 检查该行操作列中"关机"按钮
   - **预期**: "关机"按钮为可点击状态（启用，高亮显示）
3. 检查该行操作列中"启动"按钮
   - **预期**: "启动"按钮置灰（不可点击，禁用状态）
4. 检查该行操作列中"删除"按钮
   - **预期**: "删除"按钮置灰（不可点击，禁用状态）

### 步骤 4: 验证"已关机"状态主机的操作矩阵（TC-013）

1. 在列表中找到运行状态为"已关机" (stopped) 的主机行
2. 检查该行操作列中"启动"按钮
   - **预期**: "启动"按钮为可点击状态（启用，高亮显示）
3. 检查该行操作列中"删除"按钮
   - **预期**: "删除"按钮为可点击状态（启用，高亮显示）
4. 检查该行操作列中"关机"按钮
   - **预期**: "关机"按钮置灰（不可点击，禁用状态）

### 步骤 5: 验证"创建失败"状态主机的操作矩阵（TC-014）

1. 在列表中找到运行状态为"创建失败" (failed) 的主机行
2. 检查该行操作列中"删除"按钮
   - **预期**: "删除"按钮为可点击状态（启用，高亮显示）
3. 检查该行操作列中"关机"按钮
   - **预期**: "关机"按钮置灰（不可点击，禁用状态）
4. 检查该行操作列中"启动"按钮
   - **预期**: "启动"按钮置灰（不可点击，禁用状态）

### 步骤 6: 验证"删除中"过渡状态的操作矩阵（TC-015）

1. 在列表中找到运行状态为"删除中" (deleting) 的主机行
2. 检查该行的状态标签
   - **预期**: 状态标签显示为"删除中"
3. 检查该行操作列中"关机"按钮
   - **预期**: "关机"按钮置灰（不可点击，禁用状态）
4. 检查该行操作列中"启动"按钮
   - **预期**: "启动"按钮置灰（不可点击，禁用状态）
5. 检查该行操作列中"删除"按钮
   - **预期**: "删除"按钮置灰（不可点击，禁用状态）

### 步骤 7: 验证软删除主机的不可见性（TC-016）

1. 选择一台处于"已关机"或"创建失败"状态的主机
2. 点击该行"删除"按钮
3. 在弹出的二次确认对话框中点击"确定"
4. 等待删除操作完成（观察状态变为"删除中"并最终从列表消失）
5. 刷新列表页
   - **预期**: 被删除的主机记录不再出现在列表中
6. 切换分页页码或使用搜索功能
   - **预期**: 被删除的主机记录依然不可见（软删除后前端过滤 `deleted_at IS NULL`）

### 步骤 8: 验证 GET /api/v1/lecs-hosts 列表查询接口（TC-API-010）

#### 验证分页参数

1. 发送请求：`GET /api/v1/lecs-hosts?page=1&page_size=10`（携带有效认证 Cookie/Token）
   - **预期**: 返回 HTTP 200
   - **预期**: 响应体中包含主机列表数组，最多10条记录
   - **预期**: 响应体中包含分页元数据：`total`（总记录数）、`page`（当前页码）、`page_size`（每页大小）、`total_pages`（总页数）
2. 发送请求：`GET /api/v1/lecs-hosts?page=2&page_size=5`
   - **预期**: 返回第二页数据，响应中 `page` 字段为 2，`page_size` 为 5
   - **预期**: 返回的主机记录与第一页无重叠

#### 验证状态过滤参数

3. 发送请求：`GET /api/v1/lecs-hosts?status=normal`
   - **预期**: 返回结果为空或仅包含 `status` 为 `normal` 的主机记录
4. 发送请求：`GET /api/v1/lecs-hosts?status=failed`
   - **预期**: 返回结果为空或仅包含 `status` 为 `failed` 的主机记录
5. 发送请求：`GET /api/v1/lecs-hosts?status=invalid_status`
   - **预期**: 返回 HTTP 400 及字段级错误信息（或视为无效参数忽略过滤）

#### 验证响应数据格式

6. 发送请求：`GET /api/v1/lecs-hosts`
   - **预期**: 每条主机记录包含核心字段：`id`（主机ID）、`name`（主机名称）、`billing_mode`（计费模式）、`status`（运行状态）、`private_ip`（私有IP地址）
   - **预期**: 每条记录的 `status` 值为枚举值之一（creating, normal, failed, shutting_down, stopped, starting, deleting, deleted）
   - **预期**: 响应结构含成功标识（`success: true`）、数据负载（`data`）、无错误码

#### 验证错误返回

7. 发送请求：`GET /api/v1/lecs-hosts`（不携带任何认证凭证）
   - **预期**: 返回 HTTP 401 未授权错误
8. 发送请求：`GET /api/v1/lecs-hosts`（使用无权限的普通用户凭证，尝试过滤其他用户主机）
   - **预期**: 越权过滤参数被拒绝，返回 HTTP 403 禁止访问错误，或仅返回当前用户可见的主机

## 预期结果

- 列表页分页数据表格正确渲染，列结构完整（主机名/ID、计费模式、运行状态、私有IP、操作列）
- 标题栏右侧仅显示"创建LECS主机"按钮
- 每行操作列始终包含关机、启动、删除三个按钮，但根据主机状态动态启用/禁用
- 状态标签按规范渲染对应颜色：正常=绿色、已关机=灰色、创建中=蓝色、创建失败=红色、删除中=黄色
- "正常"状态主机：关机可点击，启动和删除置灰
- "已关机"状态主机：启动和删除可点击，关机置灰
- "创建失败"状态主机：仅删除可点击，关机和启动置灰
- "删除中"状态主机：三个按钮全部置灰
- 软删除后主机从列表中不可见（前端仅查询 `deleted_at IS NULL` 的记录）
- GET 列表接口支持分页参数 `page`、`page_size`，支持 `status` 状态过滤，返回标准 JSON 格式（主机列表数组 + 分页元数据），无认证返回 401，越权返回 403

## 通过标准

- 所有状态标签颜色与设计稿一致
- 操作矩阵按钮启用/禁用逻辑与规格定义完全匹配
- 软删除主机从列表页彻底消失（刷新后不可见）
- API 接口分页、过滤、错误处理均符合规格定义
- 页面无加载错误，交互流畅
