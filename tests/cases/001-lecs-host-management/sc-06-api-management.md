# SC-06: API 管理与边缘场景测试

**优先级**: P2
**质量维度**: 功能适用性、安全性、可审计性

## 前置条件

1. 系统已完成初始化，API 服务端正常运行
2. 管理员账号 `admin` / `admin@123` 已创建
3. 普通用户 A（userA）和普通用户 B（userB）已分别创建并持有有效认证凭证（JWT Cookie）
4. 用户 A 已拥有至少 1 台活跃主机（状态为"正常"）
5. 用户 B 拥有独立的主机记录（与用户 A 的主机不同）
6. API 端点基础 URL 为 `https://<host>/api/v1`

## 操作步骤

### TC-060: 验证 API 列表查询 - 普通用户权限隔离

- **优先级**: P2
- **追踪**: US-6, SC-06, TC-060

#### 步骤 1: 普通用户调用列表查询接口
1. 使用用户 A 的 JWT Cookie 认证，调用 `GET /api/v1/lecs-hosts`
2. **预期**: 返回 200 状态码，响应体中 `success: true`，`data` 中仅包含用户 A 自身拥有的主机记录

#### 步骤 2: 普通用户尝试越权过滤查询
1. 使用用户 A 的 JWT Cookie 认证，调用 `GET /api/v1/lecs-hosts?user_id=<用户B的ID>`（或其他标识其他用户的过滤参数）
2. **预期**: 返回 403 Forbidden，响应体中 `success: false`，包含错误码和"无权访问其他用户数据"类描述

#### 步骤 3: 交叉验证用户 B 的隔离性
1. 使用用户 B 的 JWT Cookie 认证，调用 `GET /api/v1/lecs-hosts`
2. **预期**: 返回 200，`data` 中仅包含用户 B 自身拥有的主机记录，不包含用户 A 的任何主机

---

### TC-061: 验证 API 列表查询 - 管理员权限

- **优先级**: P2
- **追踪**: US-6, SC-06, TC-061

#### 步骤 1: 管理员调用列表查询接口
1. 使用管理员 `admin` 的 JWT Cookie 认证，调用 `GET /api/v1/lecs-hosts`
2. **预期**: 返回 200 状态码，`success: true`，`data` 中包含全部用户（用户 A、用户 B 及其他用户）的所有主机记录

#### 步骤 2: 验证分页参数 - 第 1 页
1. 管理员调用 `GET /api/v1/lecs-hosts?page=1&page_size=5`
2. **预期**: 返回 `success: true`，`data` 中最多返回 5 条主机记录；响应包含分页元数据（`total` 总数、`page` 当前页=1、`page_size`=5、`total_pages` 总页数）

#### 步骤 3: 验证分页参数 - 第 2 页
1. 管理员调用 `GET /api/v1/lecs-hosts?page=2&page_size=5`
2. **预期**: 返回 `success: true`，`data` 中返回第 6-10 条主机记录（若总数 > 5）；`page` 值为 2

#### 步骤 4: 验证管理员可使用状态过滤
1. 管理员调用 `GET /api/v1/lecs-hosts?status=normal`
2. **预期**: 返回 `success: true`，`data` 中仅包含状态为"正常"的主机（跨越所有用户）

---

### TC-062: 验证 API 无认证拒绝

- **优先级**: P2
- **追踪**: US-6, SC-06, TC-062

#### 步骤 1: 不带凭证调用列表查询接口
1. 不使用任何认证凭证（无 JWT Cookie、无 Service Token），调用 `GET /api/v1/lecs-hosts`
2. **预期**: 返回 401 Unauthorized，响应体中 `success: false`，包含错误码（如 `UNAUTHORIZED`）和"未提供认证凭证"类描述

#### 步骤 2: 不带凭证调用创建接口
1. 不带认证，调用 `POST /api/v1/lecs-hosts`，请求体含完整创建参数
2. **预期**: 返回 401 Unauthorized，`success: false`，包含错误码和错误描述

#### 步骤 3: 不带凭证调用关机接口
1. 不带认证，调用 `POST /api/v1/lecs-hosts/{任意主机ID}/stop`
2. **预期**: 返回 401 Unauthorized，`success: false`

#### 步骤 4: 不带凭证调用删除接口
1. 不带认证，调用 `DELETE /api/v1/lecs-hosts/{任意主机ID}`
2. **预期**: 返回 401 Unauthorized，`success: false`

---

### TC-API-060: 验证 API 统一响应格式

- **优先级**: P2
- **追踪**: US-6, SC-06, TC-API-060

#### 步骤 1: 验证成功响应格式 - 列表查询
1. 使用有效认证调用 `GET /api/v1/lecs-hosts?page=1&page_size=10`
2. **预期**: 响应体 JSON 结构为 `{ "success": true, "data": [...] }`，**不包含** `error_code` 和 `error_description` 字段

#### 步骤 2: 验证成功响应格式 - 创建主机
1. 使用有效认证调用 `POST /api/v1/lecs-hosts`，提交合法的完整创建请求体
2. **预期**: 响应体 JSON 结构为 `{ "success": true, "data": {主机对象} }`，不含 `error_code`/`error_description`

#### 步骤 3: 验证成功响应格式 - 关机
1. 对状态为"正常"的主机调用 `POST /api/v1/lecs-hosts/{id}/stop`
2. **预期**: 响应体 JSON 结构为 `{ "success": true, "data": {...} }`，不含错误字段

#### 步骤 4: 验证成功响应格式 - 删除
1. 对状态为"已关机"的主机调用 `DELETE /api/v1/lecs-hosts/{id}`
2. **预期**: 响应体 JSON 结构为 `{ "success": true, "data": {...} }`，不含错误字段

#### 步骤 5: 验证失败响应格式 - 参数错误
1. 使用有效认证调用 `POST /api/v1/lecs-hosts`，提交缺少必需字段的请求体
2. **预期**: 响应体 JSON 结构为 `{ "success": false, "error_code": "<错误码>", "error_description": "<错误描述>" }`，可选含 `data` 字段但 `success` 必为 `false`

#### 步骤 6: 验证失败响应格式 - 权限错误
1. 用户 B 调用 `POST /api/v1/lecs-hosts/{用户A的主机ID}/stop`
2. **预期**: 响应体 JSON 结构为 `{ "success": false, "error_code": "<错误码>", "error_description": "<错误描述>" }`

#### 步骤 7: 验证格式一致性
1. 对比上述成功/失败响应的 JSON 结构
2. **预期**: 所有成功响应的顶层键完全一致（`success` + `data`）；所有失败响应的顶层键完全一致（`success` + `error_code` + `error_description`）

### TC-API-061: 验证 API 参数校验

- **优先级**: P2
- **追踪**: US-6, SC-06, TC-API-061

#### 步骤 1: 提交缺少必需字段（计费模式）的创建请求
1. 使用有效认证调用 `POST /api/v1/lecs-hosts`，请求体中省略 `billing_mode`（计费模式）字段，其他字段合法
2. **预期**: 返回 400 Bad Request，`success: false`，`error_description` 中包含"计费模式"或 `billing_mode` 相关的字段级错误信息

#### 步骤 2: 提交缺少必需字段（主机名）的创建请求
1. 使用有效认证调用 `POST /api/v1/lecs-hosts`，请求体中省略 `hostname`（主机名）字段
2. **预期**: 返回 400，`success: false`，错误信息中包含"主机名"或 `hostname` 相关的字段级提示

#### 步骤 3: 提交缺少必需字段（访问凭据）的创建请求
1. 使用有效认证调用 `POST /api/v1/lecs-hosts`，请求体中省略 `credentials`（访问凭据）字段
2. **预期**: 返回 400，`success: false`，错误信息中包含凭据相关的字段级提示

#### 步骤 4: 提交缺少必需字段（实例规格）的创建请求
1. 使用有效认证调用 `POST /api/v1/lecs-hosts`，请求体中省略实例规格字段（如 `instance_type` 或 `spec`）
2. **预期**: 返回 400，`success: false`，错误信息中包含实例规格相关的字段级提示

#### 步骤 5: 提交主机名格式错误的请求
1. 使用有效认证调用 `POST /api/v1/lecs-hosts`，主机名设置为 `_invalid`（下划线开头，违反命名规则）
2. **预期**: 返回 400，`success: false`，`error_description` 中明确指出主机名格式不合法

#### 步骤 6: 提交 IP 地址格式错误的请求
1. 使用有效认证调用 `POST /api/v1/lecs-hosts`，IP 配置中设置 IP 地址为 `999.999.999.999`（非法 IPv4）
2. **预期**: 返回 400，`success: false`，错误信息中明确指出 IP 地址格式不合法

#### 步骤 7: 提交密码长度不符合要求的请求
1. 使用有效认证调用 `POST /api/v1/lecs-hosts`，密码设置为 `Ab1`（少于 8 字符）
2. **预期**: 返回 400，`success: false`，错误信息中明确指出密码长度不满足要求（8-32 字符）

#### 步骤 8: 验证多字段同时错误
1. 使用有效认证调用 `POST /api/v1/lecs-hosts`，同时提交主机名 `_invalid` 和 IP `999.999.999.999`
2. **预期**: 返回 400，`success: false`，`error_description` 中同时包含主机名和 IP 地址两个字段级别的错误信息

### EC-003: 并发操作冲突防护

- **优先级**: P2
- **严重程度**: 高
- **追踪**: EC-003

#### 步骤 1: 确认主机处于"关机中"过渡状态
1. 找到一台状态为"正常"的主机，通过前端或 API 发起关机操作
2. **预期**: 主机状态变为"关机中"

#### 步骤 2: 验证前端按钮禁用
1. 在主机"关机中"状态下，查看列表页该主机的操作列
2. **预期**: 关机、启动、删除三个按钮全部置灰（不可点击、disabled 属性存在）

#### 步骤 3: 通过 API 并发发起启动请求
1. 不经过前端，直接通过 API 调用 `POST /api/v1/lecs-hosts/{id}/start`，发送启动请求
2. **预期**: 返回错误状态码（403 或 409 Conflict），`success: false`，`error_code` 包含并发操作相关的错误标识（如 `CONFLICT` 或 `INVALID_STATE`），`error_description` 说明"主机正在执行关机操作，无法重复操作"

#### 步骤 4: 通过 API 并发发起删除请求
1. 在主机仍为"关机中"状态下，直接通过 API 调用 `DELETE /api/v1/lecs-hosts/{id}`
2. **预期**: 返回错误状态码（403 或 409），`success: false`，错误信息说明主机处于过渡态不可删除

#### 步骤 5: 等待操作完成后再发起新操作
1. 等待约 10 秒，确认主机状态变为"已关机"
2. 再次调用 `POST /api/v1/lecs-hosts/{id}/start`
3. **预期**: 返回 200，`success: true`，主机正常进入启动流程

---

### EC-004: 表单提交前未填写校验

- **优先级**: P2
- **严重程度**: 中
- **追踪**: EC-004

#### 步骤 1: 实例规格未选时尝试提交
1. 用户导航至 `/console/lecs-hosts/create` 创建表单页
2. 填写其他必填字段（主机名、凭据、计费模式、购买时长等），但**不选择任何实例规格**
3. 点击"立即购买"按钮
4. **预期**: 表单不提交，且在实例规格选择区域下方展示错误提示（如"请选择实例规格"），按钮保持可点击状态但不触发提交流程

#### 步骤 2: 输入非法 IP 格式后尝试提交
1. 在创建表单中，IP 分配方式选择"手工配置"
2. 在"IP 地址"字段输入 `999.999.999.999` 或其他非标准 IPv4 格式
3. 填写其他所有必填字段，选择合法实例规格
4. 点击"立即购买"按钮
5. **预期**: 表单不提交，IP 地址输入框下方展示格式错误提示（如"请输入合法的 IPv4 地址"）

#### 步骤 3: 同时存在多个校验错误
1. 实例规格不选 + IP 地址填 `abc.def.ghi.jkl`
2. 点击"立即购买"
3. **预期**: 在实例规格区域和 IP 地址区域**同时**展示对应错误提示，表单不被提交

#### 步骤 4: 所有字段填写合法后提交成功
1. 修正所有错误字段，选择合法实例规格和合法 IP 地址
2. 点击"立即购买"
3. **预期**: 弹出确认对话框（与 TC-029 一致），表单校验通过

### EC-006: 角色权限越权防护

- **优先级**: P2
- **严重程度**: 高
- **追踪**: EC-006

#### 步骤 1: 用户 B 尝试停止用户 A 的主机
1. 获取用户 A 的主机 ID（记为 `host_id_A`）
2. 使用用户 B 的 JWT Cookie 认证，调用 `POST /api/v1/lecs-hosts/{host_id_A}/stop`
3. **预期**: 返回 403 Forbidden，`success: false`，`error_code` 包含权限相关标识（如 `FORBIDDEN` 或 `ACCESS_DENIED`），`error_description` 说明"无权操作该主机"

#### 步骤 2: 用户 B 尝试删除用户 A 的主机
1. 使用用户 B 的 JWT Cookie 认证，调用 `DELETE /api/v1/lecs-hosts/{host_id_A}`
2. **预期**: 返回 403 Forbidden，`success: false`，`error_code` 为权限拒绝类错误码，`error_description` 说明无权删除

#### 步骤 3: 用户 B 尝试启动用户 A 的主机
1. 使用用户 B 的 JWT Cookie 认证，调用 `POST /api/v1/lecs-hosts/{host_id_A}/start`
2. **预期**: 返回 403 Forbidden，`success: false`

#### 步骤 4: 用户 B 尝试查询用户 A 的主机详情（若存在单机查询接口）
1. 使用用户 B 的 JWT Cookie 认证，调用 `GET /api/v1/lecs-hosts/{host_id_A}`
2. **预期**: 返回 403 Forbidden 或返回空结果（取决于接口设计，但绝不能返回用户 A 的主机数据）

#### 步骤 5: 验证用户 A 自身操作权限正常
1. 使用用户 A 的 JWT Cookie 认证，调用 `POST /api/v1/lecs-hosts/{host_id_A}/stop`（主机状态为"正常"时）
2. **预期**: 返回 200，`success: true`，操作正常执行

### EC-007: 审计日志记录

- **优先级**: P2
- **严重程度**: 中
- **追踪**: EC-007

#### 步骤 1: 创建主机并验证审计日志
1. 使用用户 A 的认证，通过前端或 API 创建一台新主机
2. 创建完成后，通过审计日志查询接口或数据库查询审计记录
3. **预期**: 存在对应的审计日志记录，包含：
   - **操作人身份**: 用户 A 的标识（用户名或用户 ID）
   - **时间戳**: 操作发生的精确时间（格式如 `2026-05-11T10:30:00Z`）
   - **IP 地址**: 发起请求的客户端 IP 地址
   - **操作详情**: 操作类型为"创建主机"，包含被创建主机的 ID 和名称

#### 步骤 2: 关机操作并验证审计日志
1. 使用用户 A 的认证，对一台状态为"正常"的主机执行关机操作
2. 查询审计日志
3. **预期**: 存在关机操作的审计记录，包含操作人、时间戳、IP 地址、操作类型"关机"、目标主机 ID

#### 步骤 3: 启动操作并验证审计日志
1. 等待主机关机完成后，使用用户 A 的认证执行启动操作
2. 查询审计日志
3. **预期**: 存在启动操作的审计记录，包含操作人、时间戳、IP 地址、操作类型"启动"、目标主机 ID

#### 步骤 4: 删除操作并验证审计日志
1. 使用用户 A 的认证，对一台"已关机"主机执行删除操作
2. 查询审计日志
3. **预期**: 存在删除操作的审计记录，包含操作人、时间戳、IP 地址、操作类型"删除"、目标主机 ID

#### 步骤 5: 验证管理员操作同样被审计
1. 使用管理员 `admin` 的认证，执行任意主机操作（如查看列表、操作某台主机）
2. 查询审计日志
3. **预期**: 管理员操作同样被记录，操作人身份为 `admin`，其余字段（时间戳、IP、操作详情）完整

#### 步骤 6: 验证审计日志不可篡改性
1. 查询某条审计日志记录
2. 检查该记录是否包含任何修改痕迹或签名信息（若系统有设计）
3. **预期**: 每条审计记录为只读，不允许被修改或删除（至少在应用层面无删除/编辑审计日志的接口）

## 预期结果

- **TC-060/TC-061**: 普通用户仅能查看自身主机列表；管理员可查看全局主机列表；分页和过滤参数均正常工作
- **TC-062**: 所有 API 端点在无认证情况下统一返回 401 Unauthorized
- **TC-API-060**: 所有 API 响应遵循统一格式：成功时 `{success: true, data: ...}`，失败时 `{success: false, error_code: ..., error_description: ...}`
- **TC-API-061**: 缺少必需字段或字段格式错误时，API 返回 400 并提供明确的字段级错误信息
- **EC-003**: 主机在过渡态时前端禁用所有操作按钮，后端拒绝非法并发请求
- **EC-004**: 表单未填写完整或含非法值时提交被拦截，错误提示展示在对应字段下方
- **EC-006**: 用户 B 无法通过 API 操作用户 A 的主机（关机/删除/启动均返回 403），权限隔离有效
- **EC-007**: 所有主机操作（创建/关机/启动/删除）均被审计记录，记录包含操作人、时间戳、IP 地址和操作详情

## 通过标准

- 所有测试用例（TC-060, TC-061, TC-062, TC-API-060, TC-API-061, EC-003, EC-004, EC-006, EC-007）的每个步骤均达到预期结果
- API 响应格式在所有端点中保持一致
- 权限隔离无绕过路径：普通用户无法访问/操作其他用户数据
- 审计日志完整记录所有操作的 4 要素（操作人、时间戳、IP、详情）
