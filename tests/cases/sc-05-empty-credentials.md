# SC-05: 空凭证提交拦截

**优先级**: P1
**质量维度**: 功能适用性、易用性

## 前置条件

1. 用户处于登录页面
2. 用户名和密码输入框均初始化为空

## 操作步骤

### 测试组 1: 用户名空，密码有值
1. 用户名输入框留空
2. 密码输入框输入任意字符（如 `pass`）
3. 点击"登录"按钮
4. **预期**: 提交按钮被禁用或点击后提示"请输入用户名"
5. **预期**: 不进行认证请求（或返回 400 Bad Request）

### 测试组 2: 用户名有值，密码空
1. 用户名输入框输入 `admin`
2. 密码输入框留空
3. 点击"登录"按钮
4. **预期**: 提交按钮被禁用或点击后提示"请输入密码"
5. **预期**: 不进行认证请求

### 测试组 3: 两者皆空
1. 用户名和密码输入框均留空
2. 点击"登录"按钮
3. **预期**: 提交按钮被禁用或点击后提示"请输入用户名/密码"
4. **预期**: 不进行认证请求

## 预期结果

- 空输入被客户端拦截（表单验证）或服务端返回 400
- 显示明确的必填项缺失提示
- 不发送无意义的认证请求

## 通过标准

- 提交按钮在空输入时禁用，或点击后显示验证提示
- 无认证请求发生（或收到 400 响应）
- 错误提示清晰指明缺失的字段

## 质量维度映射

- **功能适用性**: 空输入拦截逻辑正确
- **易用性**: 提示清晰，用户知道需要填写哪个字段
